# Session 2026-08-28

Scope: Turn the empty Hatch package into a playable furin CLI, then record the
product decisions and bump the version to 0.1.0.

- Topic: Product shape
  - Decision: Ship a Python CLI that synthesizes furin strikes and plays them
    under a wandering-wind scheduler, with optional WAV export.
  - Rationale: The repository was already a Hatch/src-layout package named
    `hooring` (帆 + 風鈴). A CLI plus a small `render()` API matches that
    layout better than a GUI or a sample-playback toy.

- Topic: Development environment
  - Decision: Manage the venv and lockfile with uv; pin Python 3.12; keep
    hatchling only as the build backend.
  - Rationale: Local pip install is blocked by PEP 668. uv gives a
    reproducible `.venv` and `uv.lock` without Hatch env plugins.

- Topic: Strike length
  - Decision: Cut partial decay times to about half of the first draft and
    cap a strike buffer at 4 s.
  - Rationale: The first glass ring lingered as ちりーーーーん. A real Edo
    furin is closer to ちりん. Halving tau is the direct control for
    perceived length.

- Topic: Length variation
  - Decision: Draw a per-strike decay scale uniformly from 0.50 to 1.25 and
    size the buffer from that scale.
  - Rationale: Fixed length sounded mechanical. The range stays around the
    shortened mean so occasional long rings do not restore the old sustain.

- Topic: Overlapping strikes
  - Decision: Retrigger is monophonic. A new strike fades the previous ring
    over about 8 ms and replaces it.
  - Rationale: Additive overlap sounded like two furin hanging at once. One
    bell cannot keep the old vibration when the clapper hits again.

- Topic: Glass-ward timbre
  - Decision: Weaken glass overtones, soften the clapper noise/chirp, and
    give the fundamental a slightly stronger beat. Leave metal presets as
    the darker path.
  - Rationale: Default glass still read as metallic. A modest, not wholesale,
    shift keeps a ping without a clang.

- Topic: Master volume
  - Decision: Add `--volume` in 0–1, where 1 is the loudness of the current
    mix. Reject values above 1.
  - Rationale: Listeners asked to turn the existing level down, not to make
    it louder. Per-strike loudness already varies with wind speed and a
    0.7–1.15 random factor; the flag is a ceiling on that variation.

- Topic: User-facing language
  - Decision: English for README, package description, argparse help, status
    lines, and playback errors.
  - Rationale: Code comments and exception text were already English.
    Mixing Japanese CLI copy with English errors was inconsistent.

- Topic: Version 0.1.0
  - Decision: Bump `hooring.__about__.__version__` from `0.0.1` to `0.1.0`
    in a dedicated commit.
  - Rationale: `0.0.1` was the Hatch scaffold. The CLI now plays, writes
    WAV, and has the sound-design choices above, which is an initial
    functional release. Stay on 0.y.z while the interface can still move;
    1.0.0 would over-claim stability.
  - Result: `uv run hooring --version` reports `hooring 0.1.0`. Tests
    passed (`uv run pytest`, 25 tests).

- Topic: Public release notes
  - Decision: Add `release-notes.md` in the zstarview layout: an empty
    `Unreleased` section at the top, then `0.1.0 - 2026-08-28` with
    user-facing shipped behavior. Link it from the README.
  - Rationale: Version bumps in zstarview move Unreleased bullets into a
    dated section. Starting that file at 0.1.0 keeps later bumps mechanical
    and keeps internals (uv, Hatch, decay constants) in `dev-notes/` instead.

- Topic: Hourly stereo rearrangement
  - Decision: After 3600 s of scene time, reassign pan and gain with the
    same left-to-right slots, shuffled onto the existing chimes. Keep f0
    and material. Leave voice indices unchanged so min-gap and pending
    bounces still point at the same bell.
  - Rationale: Placement was fixed for the whole run. An hour is long
    enough that a new hanging feels like the breeze moved the tanzaku
    cluster, without inventing new bells. Scene time, not wall clock, so
    WAV export and live play agree.
  - Result: `uv run pytest` covers `reposition_chimes` and a 50 ms
    interval on `Scene`.

- Topic: Hourly timbre change and higher pitch
  - Decision: On each hourly rearrange, call `choose_chimes` again so
    pitch, glass/metal, pan, and gain all refresh. `--material` still
    bounds the mix. Raise glass to F7–E8 and metal to D6–D7. Shuffle
    mixed kinds instead of locking even indices to glass.
  - Rationale: Keeping the same bells made the hour mark only a stereo
    shuffle. A new hanging should also sound like different glass and
    iron. The old metal pool started at A5 (880 Hz) and read as a low
    bell; glass started at D7. Lifting both keeps the glass/metal split
    without the duller bottom.
  - Result: Unreleased notes updated. Tests cover raised pools, mixed
    material reshuffles, and scene-level rearrange.

- Topic: Pitch set: restore the top, drop the bottom
  - Decision: Put the high end back to the original C8 (glass) and A6
    (metal). Remove D7 from glass and A5/B5 from metal. Do not keep the
    F7–E8 / D6–D7 lift.
  - Rationale: The extra D8/E8 and B6/D7 sat too high. The dull notes
    were the old floor (glass D7, metal A5–B5), not a missing ceiling.
  - Result: Glass E7–C8, metal C#6–A6.

- Topic: 1/f fluctuation for loudness and spacing
  - Decision: Replace the Ornstein–Uhlenbeck wind plus Poisson strikes
    with two Voss–McCartney 1/f streams. One maps to inter-strike
    interval (`mean_gap * ratio^x`), the other to clapper strength.
    Keep `--wind` as breeze/moderate/gusty presets of those maps. Drive
    the scene from an event clock instead of a 10 ms hop. Bounces stay
    mechanical and do not consume a 1/f interval sample. First hit is
    still 0.25–0.9 s so playback is not silent at start.
  - Rationale: OU is closer to brown (1/f²) and the extra uniform jitter
    on strength was white. The request was 1/fゆらぎ on both the
    loudness series and the gap series. Independent streams let a loud
    hit follow a long quiet, which a single shared breeze parameter
    would forbid. Event-based sampling makes the sequences themselves
    1/f rather than a 1/f-modulated Poisson.
  - Alternatives Considered: One shared 1/f breeze for both — rejected
    because loudness and gap would be a monotone pair. IIR pink per
    audio hop — rejected because the user asked about strike events,
    not a continuous noise field.
  - Result: `Flicker` plus `Wind.next_interval` / `next_strength`.
    Tests cover replay, range, low-frequency dominance, preset density,
    and independence of the two streams.

- Topic: Faster ring decay
  - Decision: Halve every partial decay time constant (glass and metal).
    Leave per-strike `DECAY_SCALE` and the 4 s buffer cap as they are.
  - Rationale: The rings still lingered. Tau is the direct control for
    how long the volume takes to fall; half tau is half the time. The
    scale range and buffer cap already encode strike-to-strike variation
    and a hard stop, not the mean length.
  - Result: Glass fundamental tau 0.62 → 0.31, metal 1.45 → 0.725.

- Topic: Fewer strikes
  - Decision: Triple `mean_gap`, `min_gap`, and `max_gap` on every wind
    preset so the 1/f interval series fires about one-third as often.
    Leave `gap_ratio`, loudness flicker, and the 0.25–0.9 s first hit.
  - Rationale: The bells were busy. Scaling the gap maps keeps breeze /
    moderate / gusty relative and keeps 1/f shape. The intro hit still
    avoids a long silence at start.
  - Result: moderate mean gap 1.3 s → 3.9 s.

- Topic: Version 0.1.1
  - Decision: Bump `hooring.__about__.__version__` from `0.1.0` to
    `0.1.1` in a dedicated commit, and move the Unreleased bullets into
    `0.1.1 - 2026-08-28`.
  - Rationale: The hanging rearrange, pitch floor, 1/f timing, slower
    strike rate, and faster decay are user-facing since 0.1.0. Stay on
    0.y.z; this is a patch of sound-design changes, not a new interface.
  - Result: `uv run hooring --version` reports `hooring 0.1.1`.

- Topic: Wind chime emoji in the README
  - Decision: Put 🎐 on the README title (`# hooring 🎐`). Leave the
    package description, CLI banner, and release notes unchanged.
  - Rationale: Unicode already has a furin glyph. The title is the most
    visible place; CLI copy stays ASCII-stable for terminals that still
    mishandle emoji. Not user-facing shipped behavior, so no Unreleased
    bullet.

- Topic: End-user install via pipx
  - Decision: Lead README Installation with
    `pipx install git+https://github.com/tos-kamiya/hooring.git`. Move
    `uv sync` / `uv run pytest` under a Development subsection. Drop
    `uv pip install hooring`.
  - Rationale: uv is the contributor workflow. pipx is the usual way to
    put a GitHub-only CLI on PATH without a venv. The package is not on
    PyPI, so the GitHub git+ URL is the install source. `uv pip install
    hooring` would look for PyPI and is redundant with `uv sync`.
  - Result: Unreleased notes mention the pipx guide. Git remote is
    `tos-kamiya/hooring` (not the Hatch-scaffold GitHub URLs in
    pyproject.toml).
